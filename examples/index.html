PacEditor examples

Working pages that show how to use PacEditor. Each one is a single HTML file you can copy. The comments in the source explain each step.

Run them locally

npm install
npm run dev        # builds dist/ on change and serves the project
# open http://localhost:8000/examples/

The Basic example also works when opened directly as a file. The others need a local server, because browsers block ES modules and fetch on file://.

Getting started

Basic script tags

The smallest working setup: one stylesheet, two scripts and a container with a height.

  • Loads Quill for rich text (optional; without it the Text block uses a plain textarea).
  • Starts from inline page data in the Puck shape: { root: { props }, content: [...] }.
  • Autosaves a draft in this browser with storageKey.
  • Shows where to send the page to your server in onPublish, and renders it to HTML with PacEditor.render.

Demo full sample page

A complete page with nested layouts (Columns, Card grid), pictures and rich text. Try dragging blocks, the Tablet and Mobile widths, and dark mode.

  • Loads page data with fetch from data/sample-page.json.
  • exampleData adds Load example to the Import dialog.
  • publishLabel renames Publish to “Publish & view”, and onPublish opens a public page that renders the saved data with only the block styles.

Customising the editor

Toolbar & events new

How to fit the editor into your own app: choose which buttons it shows, add your own, and react to what the user does.

  • Hides Preview, Import and the viewport buttons with the toolbar option.
  • Adds a Save draft button next to Publish. Its onClick returns a promise, so the button is disabled while saving.
  • An app bar outside the editor calls setPreview(), setViewport(), undo() and openImport(), so the hidden features still work.
  • Listens to select, change, preview, viewport, publish and import, through the on option and editor.on(), and logs them below the editor.
  • Warns before leaving the page when there are changes that were not saved.
  • Select the Text block and use the full-screen button in its toolbar to edit long text (Esc to exit).

This example loads the build from this repository, because these features are not yet in the version on npm.

Custom blocks ES module

How to add your own blocks with extendConfig, starting from the built-in ones.

  • Quote uses a richtext field, rendered safely with renderRich.
  • Stats uses an array field with defaultItemProps, getItemSummary and max.
  • Rating uses a custom field (a range slider) that calls onChange.
  • Removes the built-in Spacer block and groups the new blocks in a palette category.
  • Each render escapes values with esc() and checks links with safeUrl(). The block styles are scoped under .fp-site.

Showing pages to visitors

Server render Node.js

Turns saved page data into a static HTML file, with no browser or DOM. Use the same code inside a route handler (Express, Fastify, Next.js, a worker).

  • Imports from pac-editor/render, which has no DOM dependency.
  • Checks the data with validateData before rendering.
  • The page only needs blocks.min.css, not the editor styles.
npm run build
node examples/server-render/render.mjs   # writes examples/server-render/output.html
